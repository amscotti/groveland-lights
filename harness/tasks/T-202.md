## Deliverable — package `internal/img` with this frozen API

```go
package img

import "errors"

var (
    ErrTooLarge        = errors.New("img: above the size limit")
    ErrPixelBomb       = errors.New("img: above the pixel limit")
    ErrUnsupported     = errors.New("img: unsupported image format")
)

// ReadOrientationJPEG returns the EXIF orientation 1..8 of a JPEG, or 1 when
// absent, truncated or corrupt. Hand-written APP1/TIFF parser (decision: no
// EXIF library dependency).
func ReadOrientationJPEG(b []byte) int

type Options struct {
    MaxBytes  int64 // bytes, before decode
    MaxPixels int   // width*height cap from DecodeConfig, before full decode
    MaxEdge   int   // long-edge cap of the output
}

type Result struct {
    JPEG   []byte // re-encoded, orientation applied, metadata-free
    Width  int
    Height int
}

// Process validates, decodes, applies EXIF orientation, scales so the long
// edge is <= MaxEdge (never upscales), and re-encodes as JPEG (quality 85).
// Every input pixel must survive the transform except the resize itself.
func Process(b []byte, o Options) (Result, error)
```

Rules frozen by the contract:

- Size check first (`len(b) > MaxBytes` → `ErrTooLarge`); then
  `image.DecodeConfig` (`MaxPixels` violation → `ErrPixelBomb`) — decode config
  only, never a full decode of a bomb; then full decode.
- JPEG via stdlib; PNG via stdlib; WebP via `golang.org/x/image/webp` (this is
  your only allowed new dependency — if `go mod tidy` pulls in ANY other module,
  write `BLOCKED: transitive deps <list>` in your handoff and stop).
- HEIC sniff: bytes 4..8 == "ftyp" with a heic-family brand → `ErrUnsupported`
  (the HTTP layer renders "please choose JPEG" for it). Undecodable bytes →
  `ErrUnsupported`. Trust magic bytes/content, never the filename.
- Orientation: apply by rotating/flipping the decoded image BEFORE re-encode
  (so a portrait Orientation=6 photo comes out landscape-correct); the output
  must contain NO APP1/APP2/EXIF/XMP segments at all (stdlib re-encode already
  drops them — keep it that way).
- Resize with `golang.org/x/image/draw` (CatmullRom or better), aspect
  preserved; images already within MaxEdge are only re-encoded, never enlarged.

## Tests (table + property + fuzz seed, in internal/img/)

- Table tests per fixture file: portrait-orient6-gps.jpg → output 800×600
  (wider than tall) with a KNOWN pixel assertion (compare a corner region of the
  rotated result against the source's corresponding corner) and no APP1 segment
  (byte-scan the output); orient8 → 600×800-equivalent rotation; landscape.jpg
  (no EXIF) → unchanged dims; tiny.png → decodes, re-encoded as JPEG; heic.bin →
  ErrUnsupported; text-as.jpg → ErrUnsupported; pixelbomb.png → ErrPixelBomb
  WITHOUT decoding (assert via a package-internal hook or by keeping the guard
  before decode and testing the error).
- Oversize: `MaxBytes` exceeded → ErrTooLarge.
- Property tests (stdlib loops, no new deps): for every decodable generated
  input (sizes 1..2000, all 8 orientations, random aspect): long edge ≤ MaxEdge,
  no APP1/APP2 in output, dims ≥ 1, orientation 1 output equals plain resize.
- Fuzz: `FuzzReadOrientationJPEG` (seed corpus from the fixtures; must never
  panic; truncated input → orientation 1).
- ReadOrientationJPEG table: each orientation 1..8 parsed back correctly.
