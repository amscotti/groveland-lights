## Goal

Give the app a pure-Go SQLite store that applies embedded migrations at open
time and refuses to boot if an applied migration's checksum no longer matches,
plus the probe counter table. This turns A-104 fully green at the unit level
and the store half of A-103; the HTTP half is T-103's (do NOT wire anything
into `cmd/server` — you don't own it).

## Repo facts

- `migrations/` exists with only `.gitkeep`. You own it entirely.
- `go.mod` (module `github.com/amscotti/groveland-lights`, go 1.27) currently
  has NO sqlite driver. You must add `modernc.org/sqlite` (pure Go, no cgo);
  the plan pins v1.62.0 — that is `latest` today, verify with
  `go list -m modernc.org/sqlite` after resolving and record the exact version
  in your handoff.
- `sqlc.yaml` is already configured: engine sqlite, schema `migrations`,
  queries `internal/store/queries`, generated Go to `internal/store/gen`
  (`emit_interface: true`). Once any `.sql` exists under `migrations/`,
  `make generate-check` (part of `make check`) runs `sqlc generate` and fails
  if `internal/store/gen` is not committed in matching state.

### migrations/migrations.go (package migrations)

`go:embed` cannot reach parent directories, so embed the SQL from inside the
directory: `package migrations` with `//go:embed *.sql` exposing `fs.FS`
(sorted by filename = application order). sqlc ignores the `.go` file.

### internal/store — the frozen public API (T-103 compiles against this)

- `func Open(ctx context.Context, dbPath string) (*DB, error)` — opens SQLite
  (WAL mode, `busy_timeout=5000`, `foreign_keys=ON`), then runs/validates
  migrations. On checksum mismatch: return an error that names the file, e.g.
  `migration 0001_init.sql checksum mismatch (recorded X, file Y)` — the
  binary turns this into a boot refusal (A-104).
- `func (db *DB) Close() error`
- `func (db *DB) ProbeCount(ctx context.Context) (int64, error)`
- `func (db *DB) ProbeInc(ctx context.Context) (int64, error)` — atomic
  increment returning the new value (e.g. `UPDATE probe SET n = n + 1 WHERE
  id = 1 RETURNING n` inside a transaction).
- `context.Context` is the first parameter everywhere (the `noctx` linter
  enforces it). Typed errors (`ErrNotFound`-style sentinels) where useful.

### Migration runner (internal/store/migrations.go or similar)

- Bookkeeping table created by the RUNNER (not by 0001):
  `schema_migrations(version TEXT PRIMARY KEY, sha256 TEXT NOT NULL, applied_at TEXT NOT NULL)`.
- One transaction per migration file; record version (filename without
  extension), sha256 of file bytes, applied_at.
- On open: every recorded version must exist among embedded files with an
  identical sha256, else fail (A-104). Unrecorded files apply in order.
- Re-opening an up-to-date DB is a no-op.

### Queries via sqlc

Put the probe queries in `internal/store/queries/probe.sql`, run
`make generate` (allowed), and COMMIT `internal/store/gen/**`. Wrap the
generated interface in your `*DB` methods.

### Tests (unit, in `internal/store`, table-driven; case names read like assertions)

- `TestMigrationsApplyCleanly` — fresh temp DB: probe table exists, count 0.
  Assert schema shape by querying (sqlite_master / your own API). Do NOT
  create any `testdata/**golden*` file — that path is protected and not yours.
- `TestMigrationChecksumGuard` — open; then UPDATE `schema_migrations` sha256
  to a different hex (in-package you can use the driver you just added);
  re-open must fail with an error naming `0001_init.sql`.
- `TestMigrationsIdempotentOnReopen` — open twice, no error, no double-apply.
- `TestProbeIncAtomicAndPersistent` — Inc thrice concurrently is fine to skip
  if flaky; at minimum: Inc → Close → Open → ProbeCount returns last value.
- WAL settings asserted via `PRAGMA` reads.
