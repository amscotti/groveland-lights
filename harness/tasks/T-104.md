## Deliverables

### scripts/docker-entrypoint.sh (new) + Dockerfile changes

Fly volumes mount at `/data` owned by root; the app runs as uid 10001 and
cannot write there unaided. Standard pattern:

- entrypoint runs as root (`USER root` before ENTRYPOINT): if `/data` exists,
  `chown -R 10001:10001 /data` (best-effort, `|| true` for local runs without
  a mount), then drop privileges with `su-exec appuser` (`apk add --no-cache
  su-exec` — tiny) and `exec "$@"`.
- `COPY scripts/docker-entrypoint.sh` (mode 0755 via `RUN chmod`),
  `ENTRYPOINT ["/docker-entrypoint.sh"]`, `CMD ["/app/server"]`.
- Keep the build stage untouched; keep image < 40 MB; keep the pinned alpine
  minor.

### fly.toml

Add a static `[env]` block: `PORT="8080"`, `APP_ENV="prod"`,
`DB_PATH="/data/lights.db"`, `PHOTO_DIR="/data/photos"`,
`TZ="America/New_York"`, `TOWN_BBOX="42.70,-71.09,42.82,-70.96"`, and
`BASE_URL="https://groveland-lights.fly.dev"` with a comment that H5 (custom
domain) updates it. Secrets stay OUT. Change nothing else without cause; the
file already matches the plan.

### .dockerignore

Add `test-run.db`, `test-run-photos/`, `selftest*`, `harness/` — the image
needs none of them (harness/ was partially excluded via harness/runs only;
excluding the whole dir is safe and shrinks context).

### scripts/smoke.sh (new) — the deployed evidence collector

`usage: scripts/smoke.sh <BASE_URL>`; `set -euo pipefail`; steps, each
printing `smoke: <check> OK`:

1. `GET /healthz` → 200 `ok` (curl, 5 s timeout).
2. TLS: certificate expires ≥ 14 days out (`openssl s_client` piping to
   `openssl x509 -enddate`) — only when BASE_URL is https.
3. `GET /` → 200 and CSP header present.
4. Probe persistence evidence (the judge's M1 input):
   - `GET /probe` with cookie jar; extract the `csrf_token` hidden-field
     value and the count N₀ from the fragment;
   - `POST /probe` (cookie jar + `csrf_token=…`) → expect 200 (HTMX) or 303
     (plain) — accept either, re-`GET /probe`, read N₁;
   - print `smoke: probe count N₀ -> N₁`; assert N₁ = N₀ + 1;
   - also POST once with a bogus token → assert 403 and unchanged count
     (re-GET).
5. Optional flag `--smoke-suite`: run `make smoke BASE_URL=<url>` for the
   Playwright `@smoke` specs; skip with a note if `node_modules` is absent.

Header every output block with the deploy identifier (`date -u`, git sha if
available) so two runs around a deploy prove persistence. POSIX-ish bash,
no bashisms that macOS bash 3.2 chokes on (no associative arrays, no `${var,,}`).

## Advisory findings on the proposed blocks (fix when they actually land)

The "ready to apply verbatim" claim should not be taken at face value:

1. **smoke.sh `epoch_of()` BSD fallback is a likely always-fail on macOS.**
   `date -ju -f '%b %d %H:%M:%S %Y %Z'` relies on BSD strptime parsing `%Z`,
   which is unreliable; the working idiom hardcodes the literal
   (`'%b %d %H:%M:%S %Y GMT'` — openssl `notAfter=` always prints GMT). If
   `%Z` fails, every macOS run dies at `tls: cannot parse notAfter`. The
   GNU-first branch only saves Linux. Unverifiable by execution here (shell
   denied) — precisely the machine-unverified class the packet tells
   reviewers to scrutinize (`T-104.md:27-36`).
2. **`http_get()` aborts silently on curl transport failure.** Steps 1 and 4
   GETs have no `|| die`; under `set -euo pipefail` the script exits with no
   `smoke: FAIL:` line (step 3's inline curl does it correctly —
   inconsistent with the packet's "each step prints evidence" intent,
   `T-104.md:93-95`).
3. **`N₁ = N₀ + 1` is racy** against any concurrent `/probe` hit between the
   two GETs. Acceptable on a single-admin deployment; deserves a comment or
   one retry so a smoke window cannot produce a false red.
4. Minor: the `for arg in "$@"` loop lets a second positional silently
   overwrite `BASE_URL`; `extract_csrf` assumes no embedded `"` in the token
   (true for T-102's frozen unpadded-base64url tokens — worth a pinning
   comment); `grep -qi` on the CSP header is needlessly case-insensitive
   (harmless).
5. The Dockerfile / fly.toml / .dockerignore / entrypoint blocks match the
   packet to the letter (`T-104.md:62-113`): `su-exec` + `RUN chmod 0755` +
   `USER root` + ENTRYPOINT/CMD split; the seven `[env]` values verbatim;
   `.dockerignore` = current file plus `test-run.db`, `test-run-photos/`,
   `selftest*`, `harness/runs` → `harness`. Root-only-for-chown with
   immediate privilege drop is the packet-prescribed pattern, not a smell.
