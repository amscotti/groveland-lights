## Deliverable 1 — handlers (`internal/web/admin*.go`)

All wrapped in `AdminOnly`. Parse every request once at the boundary into typed
structs (`walkSubmission`, `lightEdit`); no `r.FormValue` after parsing.

- `GET /admin` → list page (template admin-list). Query `page` (1-based).
  `RecentLights(ctx, 50, (page-1)*50)`.
- `GET /admin/rows` → rows fragment ONLY for `HX-Request: true`; without it →
  303 `/admin?page=N` (HTMX contract). Fragment root element id `rows`.
- `GET /admin/walk` → walk page (template admin-walk) with a fresh CSRF token.
- `GET /admin/lights/{id}` → detail/edit page (404 via ErrNotFound); element
  `#light-pos` shows "lat, lon" at 6 dp.
- `POST /admin/lights` (multipart; call `upload.LimitBody` FIRST) — fields:
  csrf_token, label (1..120 chars), asset_no (optional, `^[A-Za-z0-9-]{1,32}$`
  when set), kind (park|building), lat, lon, accuracy_m (optional float),
  photo (optional file → `s.Photo(r)`), dup_choice (""|merge|save).
  Order of checks (freeze): parse → CSRF → bbox (`Contains`, else 422 +
  `That position is outside Groveland town bounds` in role=alert) → photo
  validation (413/415 + message) → duplicates: `LightByAssetNo` OR
  `NearbyLights(lat, lon, geo.NumberedRadiusM)` + `geo.ClassifyDuplicate`;
  duplicate and dup_choice=="" → 409 with `#dup-panel` (heading
  `Possible duplicate`, existing label+asset_no+distance, buttons `Merge` and —
  unnumbered case only — `Save anyway`; numbered case shows `Merge` and a
  cancel link). dup_choice==merge → apply photo/label onto ExistingID, no new
  row. dup_choice==save (unnumbered only; numbered+save → 422) → create.
  Success → role=status `Saved` (fragment for HX; 303 `/admin` without HX).
- `POST /admin/lights/{id}` (edit: label, asset_no) → 303 detail.
- `POST /admin/lights/{id}/delete` → `SoftDeleteLight` → 303 `/admin`.

## Deliverable 3 — `web/static/js/walk.js` (≤200 lines, `// @ts-check`, JSDoc; no console.log)

ES module, wired from admin-walk.html (`<script type="module" src=...>`; CSP
forbids inline). Behaviour:

- `navigator.geolocation.watchPosition`: update `#walk-pos` ("lat, lon" 6 dp),
  `#walk-accuracy` (`accuracy N m`), hidden lat/lon inputs.
- Accuracy gate: accuracy > 30 → `Add light here` disabled + a
  `Save anyway (low accuracy)` button appears which enables saving.
- Pin pad: `#pin` (aria-label `position pin`) draggable (pointer events) over a
  pad with a metre scale; dragging moves the effective position by the pixel
  offset (pad spans ±25 m); `#pin-pos` mirrors the effective coords; arrow keys
  nudge by 1 m (accessibility). Denied/unavailable geolocation → show
  `#manual-lat`/`#manual-lon` number inputs instead.
- Alpine (CSP build, `Alpine.data` registration — no inline expressions) or
  plain DOM, your choice; htmx drives the form posts. Include
  `<meta name="htmx-config">` on the walk page so 422/409 swap the form target
  (check the vendored htmx 2.0.11 source for the exact response-handling key).
