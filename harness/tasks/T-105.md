## Why this task exists

T-100 wrote the A-103/A-104 tests as INERT DRAFTS (`acceptance/drafts/*.txt`
and holdout `drafts/`) because the merge gate runs full `make check` per task
and red specs cannot merge. The features (T-101 store, T-102 CSRF, T-103
probe wiring) are now merged. You activate the drafts — by rename, not
rewrite — so the oracle-first property is auditable in git history: the tests
predate the feature branches and were not edited after.

## Rules of activation

1. `git mv` each draft to its runnable location:
   - `acceptance/drafts/probe.spec.ts.txt` → `acceptance/e2e/probe.spec.ts`
   - `acceptance/drafts/probe_go_test.go.txt` → `acceptance/go/probe_test.go`
   - `acceptance/drafts/migrations_go_test.go.txt` → `acceptance/go/migrations_test.go`
   - holdout drafts `<holdout>/drafts/*` → their `go/` / `e2e/` dirs.
2. Run everything. Expected: all green.
3. **If a test fails, decide which side is wrong BEFORE touching anything:**
   - The FEATURE violates the frozen contract (see T-100/T-103 packets) → do
     NOT edit the test. Write `BLOCKED: A-### unmet — <precise gap>` in your
     handoff; the planner turns it into a fix task.
   - The draft has a mechanical defect that does not change what it asserts
     (e.g. the A-104 hex-token index needs pinning, a selector that must be
     scoped, a flaky wait needing `expect.poll`) → you MAY make the minimal
     edit, and MUST list every such edit in the handoff with a one-line
     justification. Anything that weakens an assertion (looser match, removed
     check, added skip) is forbidden and will be caught by review.
4. A `t.Skip`/`test.skip`/`test.only`/`.fixme` anywhere is forbidden; the
   ratchet and reviewers enforce it.

## Repo facts

- The features: `POST /probe` + `GET /probe` + home mount (T-103), store with
  migration checksum refusal (T-101), CSRF double-submit (T-102). The exact
  UI/HTTP contract is in `harness/tasks/T-100.md` and `harness/tasks/T-103.md`
  — read both before judging any failure.
- Spawn-based Go tests use `BIN` (default `bin/server`); build it yourself:
  `go build -o bin/server ./cmd/server`. `bin/` is gitignored.
- Playwright: with `BASE_URL` env set, no webServer starts. Prefer verifying
  with an externally started server so no `test-run.db` is created; if the
  config's webServer mode is used, `test-run.db`/`test-run-photos/` are
  ignored on main — never commit them.
- The full suite (`make check`) runs at your gate: unit + acceptance-go
  (spawns its own server via `scripts/acceptance-go.sh`) + Playwright on all
  four projects + holdout (now including your activated variants, which run
  against a freshly built binary via `scripts/holdout-run.sh`).

4. Handoff `harness/handoffs/T-105.md`: the exact edits made during

   any gaps for the judge.

Edit app code, `go.mod`, the Makefile, specs' assertions, or anything outside
`acceptance/**` + `harness/protected.sha256` (+ your handoff). If the contract
itself seems wrong, `BLOCKED: <reason>` and stop.
