## Goal

Make `/probe` real: the process opens the store at boot (refusing to start on
a migration checksum mismatch — A-104's runtime half), serves a CSRF-protected
counter, and shows it on the home page. The acceptance specs are INERT DRAFTS
today (`acceptance/drafts/*.txt` from T-100) — you cannot run them; build to
the frozen contracts below EXACTLY. T-105 activates the drafts afterwards and
they must pass against your work with zero edits.

## Frozen contracts (from the drafts — match them to the byte)

Store API (T-101, merged): `store.Open(ctx, dbPath) (*store.DB, error)`,
`(db) Close()`, `(db) ProbeCount(ctx) (int64, error)`,
`(db) ProbeInc(ctx) (int64, error)`. Check T-101's handoff
(`harness/handoffs/T-101.md`) for any signature notes.

CSRF API (T-102, merged): `IssueCSRFToken(w, r) string`,
`VerifyCSRF(r, submitted) error`, sentinel `ErrCSRF`. Check
`harness/handoffs/T-102.md`.

### UI/HTTP contract (assertions in drafts reference these exact strings)

- `GET /` renders as today, plus `<section id="probe">` containing
  `hx-get="/probe" hx-trigger="load" hx-target="#probe" hx-swap="innerHTML"`
  (empty server-rendered shell; HTMX fills it). The section must also work
  without JS: see the form fallback below. No inline `on*=` handlers or
  inline styles (CSP); no `console.log`.
- `GET /probe` returns 200 with an HTML FRAGMENT (no `<html>`/`<body>`; it is
  a partial, not a page) containing:
  - heading (h2) with text exactly `Probe`
  - `<p>Count: <span id="probe-count">N</span></p>` (N = current counter)
  - a `<form>` (action `/probe`, method post) with hidden input named
    `csrf_token`, and `<button type="submit">` with accessible name exactly
    `Increment counter`; the form also carries `hx-post="/probe"`
    `hx-target="#probe"` `hx-swap="innerHTML"` so JS users get an in-place
    update.
- `POST /probe` (form field `csrf_token`):
  - valid token → 200 with the same fragment, count incremented (HTMX).
  - missing/tampered token → 403, counter unchanged.
  - WITHOUT an `HX-Request: true` header (no-JS submit) → `303` with
    `Location: /` after incrementing (the home page then shows the new count).
- Parse the form ONCE at the boundary into a typed struct (e.g.
  `parseProbePost(r) (probePost, error)`); handlers never read
  `r.FormValue` after parsing (AGENTS.md rule 6).

## Deliverables

### cmd/server/main.go (you own cmd/server/**)

Order: `config.Load` → logger → `store.Open(context, cfg.DBPath)`; on error,
log it (it names the offending migration file) and exit non-zero — this is
A-104's boot refusal. On success `defer db.Close()`, hand it to the probe
feature, then `web.New(cfg, logger)` and serve exactly as today. Graceful
shutdown unchanged.

### internal/web/probe.go (+ probe_test.go) — you own internal/web/probe*.go

- Wire the store WITHOUT touching `web.go` (not in your owns): package-level
  `SetProbeStore(*store.DB)` called from `main` before `web.New`, plus
  `init() { register(route{...}) }` for `GET /probe` and `POST /probe`
  following the existing `register`/`serverFrom` pattern in `web.go` (read
  it; don't edit it). Add a doc comment marking this scaffold for refactor
  into the Server struct next phase.
- `GET /probe`: `n, err := store.ProbeCount` (store unset or error → 500 with
  a log line); token := `IssueCSRFToken(w, r)`; render the partial with a
  small data struct (Count int64, CSRFToken string). Render partials via the
  parsed templates map the way `templates.go` exposes it (a `renderPartial`
  helper in YOUR file; do not edit `templates.go`).
- `POST /probe` per the contract above. Map `ErrCSRF` → 403 (plain-text body
  is fine), parse errors → 400, store errors → 500.
- Table tests in `probe_test.go` (httptest + temp-file store through the real
  `store.Open`): `"valid token increments"`, `"missing token 403 leaves count
  unchanged"`, `"tampered token 403"`, `"non-HTMX post redirects 303 to /"`,
  `"fragment has no html/body and no id=\"map\""`, `"GET / includes the probe
  mount section"`. Cover the no-JS path by asserting the form's plain
  attributes exist in the fragment.

### web/templates/** (you own the whole tree this task)

- `pages/index.html`: add the probe section inside `{{define "content"}}`
  (after the intro copy): the empty shell with the hx-get attributes above
  and a `<noscript>`-friendly static form is NOT needed — the section shell
  plus HTMX is enough for JS users, and the no-JS flow reaches the same form
  via a plain link: include `<a href="/probe">Probe</a>` inside the shell so
  non-JS visitors can reach the fragment page. Keep the section minimal and
  Pico-styled; this is scaffold chrome, not product UI.
- NEW `partials/probe.html`: the fragment per contract. The templates engine
  (`internal/web/templates.go`) already treats non-`pages/` templates as
  partials rendered bare — check how `parseTemplates` walks files and follow
  `base.html` block conventions.
- `TestRenderAll` in `web_test.go` renders PAGES only and uses `homeData` —
  you change neither `web.go` nor `web_test.go`; your index.html change must
  render fine with the existing `homeData` fixture (pure static markup — it
  will). html-validate runs over rendered pages: keep clean semantics
  (heading levels, lang-neutral, no stray attributes).
