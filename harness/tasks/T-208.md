## Context

Two recorded findings land here, and every later task compiles against the
result:

1. The SCAFFOLD note in `internal/web/probe.go` (read it) says the store should
   live on `Server` once web.go ownership allows — Phase-2 tasks need it
   (`s.Store`), otherwise each feature repeats a package-global setter and
   every one of them would have to edit `cmd/server/main.go`.
2. Judge-M1 blocking-adjacent finding (harness/findings/judge-M1.md, "Gap (b)"):
   `probeGet`/`renderPartial` never set `Content-Type`, so with global nosniff
   the `/probe` fragment page is served `text/plain` and no-JS visitors see
   escaped source. Judge's path-to-done item 4: fix + a header assertion in the
   probe table tests.

## Deliverable 1 — store onto Server

- `web.go`: `Server` gains exported field `Store *store.DB`; `New` signature
  becomes `New(cfg config.Config, log *slog.Logger, db *store.DB) (*Server, error)`
  (nil db allowed — unit tests that never touch the store pass nil).
- `probe.go`: delete `probeStore`, `SetProbeStore`, `errProbeStoreUnset`;
  handlers read `s.Store` (nil → the same 500 error path, message
  `probe: store not wired`).
- `cmd/server/main.go`: drop `web.SetProbeStore(db)`, pass `db` to `web.New`;
  update `cmd/server/boot_test.go` for the new signature.
- `web_test.go`: `newTestServer` passes nil; probe tests that need a counter
  open a real temp store via `store.Open(ctx, filepath.Join(t.TempDir(),
  "t.db"))` (migrations apply on a temp file — fast).
- Do not change any observable probe behaviour (A-103/A-104/A-105 specs are
  active and must stay green at your gate).

## Deliverable 2 — Content-Type fix

`renderPartial` (templates.go is NOT yours — set it in the probe handlers):
`probeGet` and the HTMX branch of `probePost` set
`Content-Type: text/html; charset=utf-8` before writing the fragment. Add to
`probe_test.go` table tests: GET `/probe` and HTMX POST `/probe` responses have
exactly that header.
