## The defect (pre-existing, from T-100's web.go)

`Handler()` composes id-assigner-inner, logger-outer:

- `web.go:62` `h = s.withRequestID(h)` (inner)
- `web.go:63` `h = s.withLogging(h)` (outer)

`withRequestID` enriches only its local request (`web.go:117`), so the outer
`withLogging` still holds the pre-enrichment request when it logs
(`web.go:141`), and `requestIDOf` (`context.go:28-33`) returns the `"-"`
no-id sentinel. The response `X-Request-Id` header carries the real 16-hex
id, so every served request line disagrees with its own header. The real
binary does the same (`cmd/server/main.go:43` installs `srv.Handler()`
unchanged), so prod logs every request with `req_id:"-"`. The protected
acceptance test does not catch it: `acceptance/go/m1_guards_test.go:275-277`
checks only that the `req_id` key is present and non-empty, which `"-"`
satisfies.

## Coverage statement (the point of this attempt)

**No test in `internal/web` asserts the served chain's logged `req_id`.**
Until web.go is fixed, A-105's request-id clause is unguarded below the
acceptance suite, and nothing in this package claims otherwise:

- `TestWithLoggingRequestFields` (runs the production `s.Handler()` chain)
  asserts method, `pattern=` key presence + value, logged status
  cross-checked against the actual `rec.Code` (and `rec.Code` against the
  case's expected code), `dur_ms >= 0`, and that the response carries a real
  16-hex `X-Request-Id` — the id-assigner half of the clause, which is
  coverable and covered. It makes no assertion about the logged `req_id`;
  the deliberate non-coverage is documented in a comment at the assertion
  site.
- `jsonRequestLine` / `TestProdLoggingIsJSON` check the JSON form of the
  same coverable fields; the `req_id` check (previously key-presence /
  non-empty, which the served `"-"` satisfies) is removed, with a comment
  pointing here.
- `TestWithLoggingLogsContextRequestID` (renamed from
  `TestWithLoggingLogsRealRequestID`) is what it says: a **unit** test of
  `withLogging`'s own contract — composed inside `withRequestID` (the
  arrangement it was built for), the logged `req_id` equals the response
  `X-Request-Id` and matches `^[0-9a-f]{16}$`, never `"-"`. Its doc comment
  states explicitly that it is NOT production coverage and that whoever
  swaps the two lines in web.go should move its assertion onto
  `s.Handler()` so it guards the real chain.

Why no failing assertion was left in place: the scheduler hard-fails on
`make check-fast` before reviews run and the merge gate runs `make check`;
a deliberately red test would keep this package — which T-103 compiles
against — from ever merging. The review's sanctioned alternative ("removing/
renaming the weak assertions so they are not represented as coverage") is
what is implemented: the assertions that previously rubber-stamped `"-"` as
acceptable are gone, not weakened further.

## The owner fix (one line, web.go Handler() only)

```go
h = s.withLogging(h)      // swap with the line below
h = s.withRequestID(h)
```

After the swap, move the assertion from `TestWithLoggingLogsContextRequestID`
onto `s.Handler()` (logged `req_id` == response `X-Request-Id`, 16-hex,
never `-`). Optionally also strengthen the protected
`acceptance/go/m1_guards_test.go:275-277` from key-presence to the real-id
shape — that file belongs to acceptance/'s owner, not this task.

## Frozen API as implemented (T-103 compiles against this — unchanged)

```go
// internal/web/csrf.go — package web
const CSRFTokenName = "csrf_token" // cookie name AND hidden-input name (contract-frozen string)

var ErrCSRF = errors.New("csrf: token mismatch")

func IssueCSRFToken(w http.ResponseWriter, r *http.Request) string
func VerifyCSRF(r *http.Request, submitted string) error
```

Semantics T-103 should rely on:

- **Token format**: 32 crypto/rand bytes as unpadded base64url (43 chars).
  "Well-formed" = strict raw-url decode to >= 32 bytes, length <= 256 (DoS
  bound on hostile cookies/fields).
- **IssueCSRFToken**: a well-formed `csrf_token` request cookie is reused
  as-is with **no Set-Cookie** (idempotent per session-less phase; pinned).
  Otherwise a fresh token is minted and set: `Path=/`, `HttpOnly`,
  `SameSite=Lax`, `Secure` iff `serverFrom(r.Context()).Cfg.IsProd()`. Must
  run inside the server chain (needs the server in context, like every
  handler). On the unreachable entropy failure it answers 500 and returns "".
- **VerifyCSRF**: nil only if cookie and submission both exist, are
  well-formed, and are equal under crypto/subtle constant-time compare.
  Everything else — missing cookie, empty, garbage, short, padded,
  over-long, mismatched — is `ErrCSRF`, uniformly (answer 403, don't
  distinguish causes).
- **Usage sketch for /probe**: render: `tok := IssueCSRFToken(w, r)` then
  `<input type="hidden" name="csrf_token" value="{{.CSRFToken}}">`; POST:
  parse the form into a typed struct at the boundary, then
  `if err := VerifyCSRF(r, f.CSRFToken); err != nil { 403 }`.
