## The defect, reproduced this session

`web.go` `Handler()` composes the chain id-assigner-inner, logger-outer:

- `web.go:62` `h = s.withRequestID(h)` (inner)
- `web.go:63` `h = s.withLogging(h)` (outer)

`withRequestID` enriches the context by rebinding its **local** request
(`web.go:117` `r = r.WithContext(...)`), so the outer `withLogging` still holds
the pre-enrichment request when it logs (`web.go:141`
`requestIDOf(r.Context())`), and `context.go:28-33` returns the `"-"` no-id
sentinel. The response header `X-Request-Id` carries the real id, so every
served request line disagrees with its own header. Observed this session, in
the keeper test (run `go test ./internal/web/ -run TestWithLoggingRequestFields -v`):

```
middleware_logging_test.go:128: served-chain req_id = "-"
```

The same is true of the real binary: `cmd/server/main.go:43` installs
`srv.Handler()` unchanged, so prod logs every request with `req_id: "-"`.
A-105's contract line (`acceptance/contract.json:34-37`) requires a request id
in the log; `-` is the explicit no-id sentinel, not one.

## The owner fix (one line, in `web.go` `Handler()` only)

Swap the two compositions so the id exists before the logger runs:

```go
h = s.withLogging(h)      // was line 63
h = s.withRequestID(h)    // was line 62
```

(An equivalent alternative is having `withLogging` read
`rec.Header().Get("X-Request-Id")` after `next.ServeHTTP`.) After the swap:
`TestWithLoggingLogsRealRequestID` keeps guarding the units, the `-v` line in
`TestWithLoggingRequestFields` starts printing a real id, and the served chain
satisfies A-105's request-id clause end to end. Nothing in T-102's files needs
to change. Optionally (owner's call — the acceptance suite is protected, not
mine): strengthen `acceptance/go/m1_guards_test.go:275-277` from
key-presence to the real-id shape; today it passes on `-` too.

## Frozen API as implemented (T-103 compiles against this — unchanged)

```go
// internal/web/csrf.go — package web
const CSRFTokenName = "csrf_token" // cookie name AND hidden-input name (contract-frozen string)

var ErrCSRF = errors.New("csrf: token mismatch")

func IssueCSRFToken(w http.ResponseWriter, r *http.Request) string
func VerifyCSRF(r *http.Request, submitted string) error
```

Semantics T-103 should rely on:

- **Token format**: 32 crypto/rand bytes as unpadded base64url (43 chars).
  "Well-formed" = strict raw-url decode to >= 32 bytes, length <= 256 (DoS
  bound on hostile cookies/fields).
- **IssueCSRFToken**: a well-formed `csrf_token` request cookie is reused
  as-is with **no Set-Cookie** (idempotent per session-less phase; pinned).
  Otherwise a fresh token is minted and set: `Path=/`, `HttpOnly`,
  `SameSite=Lax`, `Secure` iff `serverFrom(r.Context()).Cfg.IsProd()`. Must
  run inside the server chain (needs the server in context, like every
  handler). On the unreachable entropy failure it answers 500 and returns "".
- **VerifyCSRF**: nil only if cookie and submission both exist, are
  well-formed, and are equal under crypto/subtle constant-time compare.
  Everything else — missing cookie, empty, garbage, short, padded, over-long,
  mismatched — is `ErrCSRF`, uniformly (answer 403, don't distinguish causes).
- **Usage sketch for /probe**: render: `tok := IssueCSRFToken(w, r)` then
  `<input type="hidden" name="csrf_token" value="{{.CSRFToken}}">`; POST:
  parse the form into a typed struct at the boundary, then
  `if err := VerifyCSRF(r, f.CSRFToken); err != nil { 403 }`.
