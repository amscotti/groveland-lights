## The fix for the BLOCK (finding #1) — `internal/store/migrations.go`

The reviewer's two offered resolutions were (a) have the canary/pin updated by its owner,
or (b) an explicit, runner-owned format change whose column type and long-term contract
are deliberate, then re-run A-104 + smoke. (a) is outside T-201's ownership — the canary
(`internal/store/dbfile_layout_test.go`) is not in `harness/policy.json`'s protected list
but is not in this task's owns either, and the T-105 index-pin exception is spent (the
A-104 header records that the frozen `locs[0]` index was kept because the first token WAS
the anchor checksum; "the oracle is never edited to fit the implementation"). So this round
implements (b), in the runner file this task owns (`internal/store/migrations*.go`):

- **Contract (`sumRecordEncoding` + `sumRecordValue`)**: `schema_migrations.sha256` stays
  `TEXT NOT NULL` and **every recorded value honours it**. The anchor row — the first
  embedded migration, `0001_init.sql` — records its digest as 64-char lowercase hex (the
  exact encoding the frozen A-104 boot contract names: "its sha256 checksum is recorded in
  schema_migrations as 64-char lowercase hex"; the byte-level tamper contract rewrites that
  token and expects boot refusal naming `0001_init.sql`). Every later migration records
  `raw-b64:` + unpadded RFC 4648 base64url of its raw digest — tagged TEXT, 43 payload
  chars, whose tag bytes and bounded length can never form or extend a 64-char hex run, so
  the anchor stays the database file's only hex token for any number of migrations. The
  positional special case is inherent to the frozen contract (only 0001's encoding is
  pinned by name); it is now explicit, uniform to decode-by-comparison, and documented in
  the runner as the runner's own long-term contract.
- **Verification (the fix's core)**: no decoding exists any more. `applyMigrations`
  recomputes the expected representation per position via `sumRecordValue` and compares
  bytes. A corrupted anchor, a wrong digest under the right tag, or a foreign encoding —
  including a later row carrying the CORRECT digest as bare hex — mismatches and refuses
  the boot naming the offending file. The old `len(raw)==64` length heuristic and the
  unconditional hex acceptance are gone (they were the reviewer's latent-contract
  complaint). The mismatch message still prints the recorded representation and the
  embedded file's checksum, so A-104's "names 0001_init.sql + checksum" wording holds.
- **Removed**: `checksumRecordValue(first, m) any` (BLOB branch), `decodeRecordedSum`,
  `sumRaw`-as-BLOB storage. DDL, apply order, idempotence, `ErrChecksumMismatch`
  semantics, and all other error messages are unchanged.

Legacy DBs written by the two never-merged attempt binaries (per-row bare hex or BLOB for
`0002_lights`) now refuse at boot — deliberately: no such DB exists outside discarded
attempt worktrees, and refusing a foreign representation is the guard working. Runtime
state can be rebuilt at any time (see "Local runtime state" below).

## Local runtime state repaired (disclosed)

`make e2e-task` initially failed because this worktree's gitignored `test-run.db` had been
written by the pre-redesign binary: its `0002_lights` row held the digest as **bare hex**
(64-char TEXT). Under the new positional contract that is a foreign representation and
boot correctly refused — with recorded and file digests IDENTICAL in the message, which is
exactly the `bare_hex_encoding_is_refused_even_with_the_correct_digest` subtest's scenario
observed in the wild. Shell file-deletion is denied in this session (`rm`, `git clean`,
`node -e` all rejected), so the repair ran as a TEMPORARY test appended to
`internal/store/migrations_test.go` (an owned file): it logged the stale representation
and the refusal, rewrote the row to the contract-correct
`raw-b64:wqbAbAQlnlueuGIycarqDSewapXqMSqtlAGUuvRIHpY`, and proved a clean boot — the
equivalent of the README-sanctioned `rm -f test-run.db*`, preserving rows. The scratch
test was then removed via edit and `git status` confirms the committed tree never carried
it. In any other environment the sanctioned fix is simply `rm -f test-run.db*`.
