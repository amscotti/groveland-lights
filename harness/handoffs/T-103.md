## Contract gaps (why this handoff is prefixed BLOCKED)

### (a) The no-JS home clause is unsatisfiable within owns — needs a web.go owner

`acceptance/drafts/probe.spec.ts.txt` (test "no-JS fallback form increments
via 303 redirect") and `acceptance/drafts/README.md` (row: "server-rendered
(with a plain form) when JS is off") require `GET /` to server-render the
probe heading, live `Count: N` in `#probe-count`, and a POST form carrying a
**live CSRF token** into the HTML response. With JavaScript off nothing
fills the section client-side, so the bytes must come from the home render.

The home render lives in `internal/web/web.go` (`homeData`/`home()` +
`templates.go`'s funcless parse). This packet forbids touching `web.go`
three times ("not in your owns"; Out of scope; "do not edit it"), and
`web_test.go`/`homeData` are likewise frozen ("you change neither").
I proved no template-only construction can inject live count/token data:
the parser accepts no funcs, `homeData` has no probe fields, and any
`{{.Probe}}`-style access errors at execution. The packet's own deliverable
("empty shell + `<a href="/probe">` link; a noscript-friendly static form is
NOT needed") therefore cannot satisfy the frozen draft — the packet is
internally inconsistent on this clause (its own UI-contract bullet says "The
section must also work without JS", matching the draft, while its
deliverable prose describes the shell).

**Required fix (≈15 lines, one owner task):** grant an owner of
`internal/web/web.go` (currently ownerless — the same file holds T-102's
blocked chain-order fix): add `Count int64` + `CSRFToken string` to
`homeData` (or embed `probeData`), have `home()` read the store and call
`IssueCSRFToken`, and change `index.html`'s section to
`{{template "partials/probe.html" .}}` (keep the four hx attributes; drop
the link). Every other file (probe handlers, fragment, CSRF, boot) is
already in place — my template renders the same partial for both flows.
Until then, T-105's activation of test #12 will fail as its rules
anticipate (BLOCKED → fix task).

### (b) The Go draft's `probeReCount` regex cannot match the packet-frozen markup

The draft pins `probeReCount = Count:\s*(\d+)` over the **raw HTML source**,
but the packet freezes the fragment line byte-exactly as
`<p>Count: <span id="probe-count">N</span></p>` — the digits sit inside the
span, so after `Count: ` the source contains `<span`, and the regex cannot
match (whitespace-backtracking still hits `<`). No markup satisfies both the
packet string and this regex; the TS draft independently requires the
digits-only span (`toHaveText(/^\d+$/)`), which is what I implemented and
tested. Assertion #2/#7's *intent* (fragment shows `Count: N`, POST returns
N+1) is fully verified by my unit rows and boot smoke. **Disposition for
T-105:** this is the sanctioned mechanical-selector class (harness/tasks/
T-105.md, "Rules of activation" §3, second bullet: "a selector that must be
scoped" is a mechanical defect that does not change what it asserts, so the
minimal edit is allowed and just listed in T-105's handoff — the regex needs
to skip the span tag or be applied to tag-stripped text; the `(\d+)` capture
and every other assertion stay identical). Note the drafts README names the
A-104 hex-token index as "the only sanctioned edit", but T-105's own packet
is the operative rule set for the activator and grants precisely this class.
Planner may alternatively re-freeze the contract string;
editing the draft is not mine to do.
