## Spec deviation, precisely (for reviewer/planner)

The packet says the signature "becomes `New(cfg config.Config, log *slog.Logger,
db *store.DB) (*Server, error)`". Delivered as `db ...*store.DB` because the
packet is self-contradictory on this point and the contradiction is
mechanically enforced:

- main's `internal/web/middleware_logging_test.go` calls `New(testConfig(env),
  slog.New(h))` — 2 args. Go has no default arguments; with a fixed-arity
  3-param `New` that line cannot compile.
- Editing that file is outside `owns` (packet: `cmd/server/**`,
  `internal/web/web.go`, `context.go`, `web_test.go`, `probe*.go`) — attempt 1
  did it anyway and the guard rejected the branch with exit 4. There is no
  exemption path in guard.go for it.
- Therefore the two packet requirements "exact 3-arg signature" and "diff stays
  inside owns" cannot both hold. The variadic third parameter is the only
  signature satisfying both "main's tests compile untouched" and "owns clean",
  while preserving every semantic requirement: `New(cfg, log, db)` is the
  frozen call form (compiles, and is what main.go and downstream tasks use),
  nil-db is allowed, `s.Store` is the frozen access path, `SetProbeStore` is
  gone, behaviour is unchanged.

If the planner prefers the literal fixed-arity signature, the one-line fix is
to extend owns (e.g. add `internal/web/middleware_logging_test.go` or
`internal/web/**`) for whichever task lands that change — the compile edit is
unavoidable the next time the signature moves.

## The header fix, precisely

With the global `X-Content-Type-Options: nosniff` (web.go `withSecurityHeaders`),
a fragment response without `Content-Type` is sniffed by Go's server: the
fragment starts with `<h2>`, which is **not** in Go's HTML sniff signature list,
so the wire response was `Content-Type: text/plain; charset=utf-8` — a no-JS
visitor hitting `/probe` directly saw escaped source (judge-M1 "Gap (b)").

Re-proven on this tree (attempt 3): with the two
`w.Header().Set(probeContentType)` lines temporarily disabled,
`TestProbeFragmentContentType` fails with
`fragment Content-Type = "text/plain; charset=utf-8"` on both rows (exit 1);
with them restored it passes (exit 0), and `git status` shows probe.go
byte-identical to HEAD afterwards. The recorder-based assertions used elsewhere in the suite cannot
see this because the recorder never sniffs — hence the wire-level
(`httptest.NewServer`) table test.
