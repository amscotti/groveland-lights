## What changed (commit a5f0c27, 13 files)

### Routes (`internal/web/admin.go`, `admin_create.go`) — all `AdminOnly`-wrapped

| Route | Behaviour |
|---|---|
| `GET /admin` | list page (template `admin-list`), query `page` 1-based, `RecentLights(51, (page-1)*50)` with one extra row to detect an older page |
| `GET /admin/rows` | rows fragment (root element `id="rows"`) only for `HX-Request`; otherwise 303 `/admin?page=N` |
| `GET /admin/walk` | walk page with a fresh CSRF token + bbox for the client-side pre-flight |
| `GET /admin/lights/{id}` | detail/edit page; `ErrNotFound` → 404; `#light-pos` shows "lat, lon" at 6 dp |
| `POST /admin/lights` | multipart; `upload.LimitBody` FIRST; frozen check order parse → CSRF → bbox 422 (`outside Groveland town bounds`, role=alert) → photo 413/415 → duplicates: `LightByAssetNo` OR `NearbyLights(NumberedRadiusM)` + `geo.ClassifyDuplicate`; dup + no choice → 409 `#dup-panel` (`Possible duplicate`; numbered: Merge + Cancel link, no Save anyway; unnumbered: Merge + Save anyway; numbered+save → 422); merge applies the new label onto ExistingID, no new row; success → role=status `Saved` fragment (HX) / 303 `/admin` |
| `POST /admin/lights/{id}` | edit (multipart or urlencoded); unspecified fields keep stored values; duplicate asset_no → 409 re-render with alert; 303 back to detail |
| `POST /admin/lights/{id}/delete` | `SoftDeleteLight` → 303 `/admin`; deleting a deleted id → 404 |

Every request is parsed once at the boundary into typed structs (`walkSubmission`,
`lightEdit`, `lightDelete`, `listQuery`, `lightIDParam`); no handler reads the form
after parsing. No new dependencies; no `Phase N` strings; no markers.

### `web/static/js/walk.js` (200 lines, `// @ts-check`, JSDoc, no console.log)

- `watchPosition` updates `#walk-pos` / `#pin-pos` (6 dp), `#walk-accuracy`
  (`accuracy N m`) and the hidden lat/lon/accuracy inputs.
- 30 m accuracy gate: `Add light here` carries the platform `disabled` attribute
  until `Save anyway (low accuracy)` is chosen (which re-enables and unlocks a
  real save at 80 m).
- Pin pad: pointer-drag (px → metres, pad spans ±25 m) + arrow-key nudges (1 m);
  `#pin-pos` mirrors the effective position; the drag/keyboard position is what
  the form submits and what `#light-pos` echoes at 6 dp.
- Denied/unavailable geolocation → manual `#manual-lat`/`#manual-lon` inputs
  (SVG pad hidden via `setAttribute('hidden')`; `.hidden` does not exist on
  SVGElement). The fallback only fires before any fix: permission overrides
  (Playwright `setGeolocation`) can surface a transient error mid-watch.
- Client-side bbox pre-flight mirrors the frozen server message
  (`That position is outside Groveland town bounds`, role=alert) on every
  position update, per the drafts README reconciliation 4.
- htmx 2.0.11 `config.responseHandling` override (4xx swap, no error event) so
  422/409 bodies swap into the form's `#dup-slot` target. The `<meta
  name="htmx-config">` required by the packet is present on the walk page via
  base.html (all pages carry `allowEval:false`); base.html is not editable by
  this task, and htmx only reads the FIRST meta (querySelector) at script eval —
  so the responseHandling array is set at module-init time, before htmx
  processes the DOM (module scripts run before DOMContentLoaded).
- Photo preview: object-URL `img#photo-preview`, replaced per file pick (the
  draft's "preview must track the picked file" clause).

## Open issues

1. **Merge does not yet apply the new PHOTO onto the survivor** (label only).
   The packet's merge clause says "apply photo/label onto ExistingID", but the
   store API has no way to set a light's photo post-create (`EditLight` takes
   label+asset only; the store is T-201's package, outside this task's owns).
   The frozen Go draft (`admin_lights_go_test.go.txt`) asserts only the label
   application, so acceptance passes; if the planner wants photo-merge, the
   store needs an `EditLightPhoto`-style method first.
2. **`Cancel` in the numbered dup panel is a plain text link** (frozen
   role=link + string; styling it as a button would change its ARIA role and
   break the frozen `getByRole('link', { name: 'Cancel' })` assertion). Its tap
   target is smaller than 44 px; all buttons meet the 44 px floor.
3. **`Delete light` is outline-styled with a red warning icon, not a red
   button** — `web/static/css/app.css` is outside this task's owns and CSP
   (`style-src 'self'`) blocks inline styles, so a true red variant needs a CSS
   task. Separation from `Save changes` is implemented (separate form).
4. The scratch Playwright harness (packet Deliverable 4) had to live under
   `web/templates/scratch/` (agent sandbox permits writes only inside owns
   globs, not repo-root `scratch/`); it is inert to the app (templates.go walks
   `.html` only) and was deleted before commit; screenshots remain in
   `test-results/`.
