## Open issues

1. **Live `/admin/login` still renders auth.go's inline minimal page** —
   unstyled (no pico.css), `Sign in` is a ~21 px native button, below the 44 px
   floor in the A-201 visual note. `auth.go` (and its `renderLoginPage`) is a
   frozen T-203 file explicitly outside this task's owns, and the mux panics on
   duplicate pattern registration, so T-205 cannot swap the page without
   touching it. The styled replacement `pages/admin-login.html` already exists
   in the pipeline (rendered by `TestRenderAll`); the fix is a 3-line change in
   `internal/web/auth.go` (`renderLoginPage` → `renderPage(…, "admin-login.html",
   pageData{Title: "Admin login", …})`) plus a `pageData` carry-through — needs
   either T-203's owner or an explicit owns extension. A-201 is T-203's claim,
   not one of T-205's (A-202/A-203/A-208/A-209); flagged for the planner.
2. **Merge applies the new label but not the new PHOTO onto the survivor** —
   the packet's merge clause says "apply photo/label onto ExistingID", but the
   store API has no way to set a light's photo post-create (`EditLight` takes
   label+asset only; `internal/store` is T-201's package, outside this owns).
   The frozen Go draft asserts only the label application, so acceptance
   passes; photo-merge needs an `EditLightPhoto`-style store method first.
3. **`Cancel` in the numbered dup panel is a plain text link** (frozen
   role=link + name; styling it as a button would change its ARIA role and
   break the frozen `getByRole('link', { name: 'Cancel' })`). Its tap target is
   below 44 px; all buttons meet the floor.
4. **`Delete light` is an outline button with a red warning icon, not a red
   button** — `web/static/css/app.css` is outside this task's owns and CSP
   (`style-src 'self'`) blocks inline styles. Separation from `Save changes` is
   implemented (separate form); a true red variant needs a CSS task.
