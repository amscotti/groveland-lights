## What changed

- **migrations/0001_init.sql** — exactly the packet's `probe` DDL + seed row
  (`id=1, n=0`). No "Phase N" strings (`make phase-grep` → 0). Append-only;
  never edit after merge.
- **migrations/migrations.go** — `package migrations`, `//go:embed *.sql`,
  exposes `Files embed.FS` (embed.FS lists entries in lexical order = the
  application order). sqlc ignores the `.go` file.
- **internal/store/store.go** — frozen API (signatures below). Driver is
  pure-Go `modernc.org/sqlite`; pragmas ride the DSN
  (`file:<path>?_pragma=journal_mode(WAL)&_pragma=busy_timeout(5000)&_pragma=foreign_keys(1)`)
  so **every** pooled connection gets them (`foreign_keys`/`busy_timeout` are
  per-connection; a one-off Exec would not cover the pool).
- **internal/store/migrations.go** — runner owns the bookkeeping table
  `schema_migrations(version TEXT PRIMARY KEY, sha256 TEXT NOT NULL,
  applied_at TEXT NOT NULL)` (`CREATE TABLE IF NOT EXISTS`, not in 0001).
  One transaction per file: exec SQL + insert row (version = filename sans
  extension, sha256 = lowercase hex of file bytes, applied_at = RFC3339 UTC).
  On open: every recorded version must match an embedded file byte-for-byte,
  else refusal naming the file and wrapping `ErrChecksumMismatch`; a recorded
  version with no embedded file also refuses. Unrecorded files apply in
  order. Reopening an up-to-date DB writes nothing.
- **internal/store/queries/probe.sql** + **internal/store/gen/** — sqlc
  v1.31.1 output (`db.go`, `models.go`, `querier.go`, `probe.sql.go`),
  generated via `make generate`, committed; `make generate-check` → 0
  (regeneration is byte-stable against the commit). `ProbeInc` uses
  `UPDATE … RETURNING n` inside a transaction (`WithTx`).
- **Tests** (in-package, table-driven, assertion-style names, no golden
  files, no skips): fresh-DB schema shape via `sqlite_master`/`PRAGMA
  table_info`; counter seeded 0 at id=1; recorded version/checksum match the
  embedded file's sha256 (64-char lowercase hex); checksum-guard refusal
  (replaced hex AND uppercase hex → `ErrChecksumMismatch`, error names
  `0001_init.sql`, says `checksum mismatch`, names both sums); idempotent
  reopen (no error, 1 row, `applied_at`/`sha256` untouched, count preserved);
  PRAGMA assertions (`journal_mode`=wal, `foreign_keys`=1,
  `busy_timeout`=5000) + `-wal` sidecar present while open; sequential incs
  return 1/2/3; persistence across Close→Open; 10 concurrent incs return
  exactly {1..10} with final count 10; `ErrNotFound` sentinel when the probe
  row is deleted; `Open` refuses a missing parent directory;
  `TestChecksumIsFirstHexTokenInDBFile` pins the on-disk layout property the
  A-104 byte-tamper draft depends on (after clean open+write+close the only
  64-hex token in the file IS the recorded checksum).

### Frozen API as implemented (T-103 compiles against this)
