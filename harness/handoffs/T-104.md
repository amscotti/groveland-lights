## What changed this attempt

All in `scripts/smoke.sh` (the only file with findings; the other four owned files were reviewer-verified packet-exact and are untouched):

1. **BLOCKER 1 fixed — `extract_csrf` doubled the token.** The sed lacked `-n`, so it auto-printed the pattern space AND the `p` flag printed it again: the token arrived as `T\nT`, the POST embedded a newline, and `VerifyCSRF` would 403 forever against a correctly deployed T-103. Now `sed -n "s/^.*value=\"\([^\"]*\)\".*$/\1/p"` (line 162), with a load-bearing comment explaining why `-n` is required (and why `extract_count` correctly has no `p`). Defense in depth added at lines 170–174: a `*[[:space:]]*` gate on the extracted token now refuses any whitespace-laden value with a clear `smoke: FAIL:` before the POST, so even a future regression of this class is diagnosed in one read instead of surfacing as an inexplicable 403.
2. **BLOCKER 2 fixed — CSP grep false-failed over HTTP/2.** `curl -D` dumps header names exactly as they crossed the wire; behind the Fly edge that is usually h2, where field names are lowercase (RFC 9113 §8.1). The case-sensitive `^Content-Security-Policy:` grep missed it — environment-dependent (passed on HTTP/1.1-only macOS system curl, failed on any HTTP/2-capable curl). Now `grep -qi "^content-security-policy:"` (line 121) with the reasoning in the comment.
3. **Minor advisory folded in — BASE_URL query/fragment trim** (lines 54–57): `BASE_URL` is now stripped at `?` and `#` right after the trailing-slash trim, so a stray query can no longer leak into the TLS host extraction or curl targets (review finding: “trimming at ? would be tidier”).

Semantic verification by reading (third pass over the final file):

- `sed -n … p` prints the captured group exactly once — `-n` suppresses sed’s end-of-cycle auto-print, so the only output is the substituted pattern space (`p` fires on successful substitution only). This is POSIX-specified sed behavior on both GNU and BSD sed; it is also precisely the fix reviewer 2 prescribed, applied verbatim. A no-match tag now yields empty output (caught by the `[ -n "$csrf" ]` gate), never mangled output.
- `grep -qi "^content-security-policy:"` matches both the h1 canonical form and the h2 lowercase wire form; `-qi` is standard POSIX grep (and matches nothing when the header is absent, so the die still fires).
- The whitespace gate runs after the non-empty check and before the POST; `[[:space:]]` in a `case` pattern is POSIX bracket-expression syntax, valid in bash 3.2 (this repo’s minimum).
- The BASE_URL trims use `"${BASE_URL%%\?*}"` (backslash-escaped `?` inside double quotes → literal `?` in the pattern) and `"${BASE_URL%%#*}"` (`#` is not special in glob patterns); both are bash 3.2-safe.
