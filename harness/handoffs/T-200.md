## Would-fail reasoning — satisfiability against a COMPLIANT M2 build

This is the analysis attempt 1 missed (review MINOR) and the reason it was
blocked; each former blocker is walked through:

- **One-time token vs 40 logins (reviewer-alt 1)**: fixed by the helper
  economy. Within one `npx playwright test`: first `loginAsAdmin` exchanges
  once; every other call reuses the validated cookie (session TTL 24 h ≫ run
  duration). Across `make check`'s e2e → a11y invocations (same
  `test-run.db`): the a11y invocation adopts the disk-cached session and
  exchanges nothing. Remaining edge: a DB older than 24 h with the token
  consumed fails loudly with the `rm -f test-run.db*` operator note — runtime
  state, gitignored, safe to delete at any time; documented in the README and
  below as an operational note for T-207.
- **Shared accumulating DB across tests/projects/runs (Blocker 2)**: every
  create uses an asset number unique per run+project (unique index can never
  fire); every unnumbered create (the 8 m radius makes coordinates a key)
  sits on per-run jittered coordinates; passing tests delete what they
  created (soft delete frees both keys), and pre-cleanup makes even a
  same-process retry (CI `retries: 1`) deterministic. A failing test can
  leave rows behind; the next run's jitter (≈11 m grid over a ~3.3 km × 2.2
  km band, keys hashed per run) makes an 8 m collision with a previous run's
  leftover effectively impossible, and pre-cleanup by label removes
  same-label strays anyway.
- **A-205 first-create-with-Saved on an existing GP-017 (Blocker 1 /
  reviewer-alt 2)**: eliminated — each test creates only uniquely-numbered
  lights; the panel is triggered by re-submitting THAT asset.
- **Redirect-following hiding the 303 (reviewer-alt 3)**: every
  `page.request.post` pins `maxRedirects: 0`; each seed asserts the raw 303.
- **A-206 depending on test 1 (reviewer-alt 4)**: it now creates its own
  photo light; `make e2e-task T=T-206` is self-sufficient.
- **`Older` link vs button (5), poll-after-drag (7), edit-status shape**:
  covered above.
- **Go drafts**: fresh spawned server + `t.TempDir()` DB per test (fresh
  token per test — replay semantics assertable), `ErrUseLastResponse`
  clients, `alDetailURL` relies only on the frozen row-link contract.

Known acceptable non-determinism, stated for the record: the jitter hash
could theoretically collide between two test keys in one run (probability on
the order of 1/90 000 per pair) — a collision would surface as a duplicate
panel on an unnumbered create, not as a silent pass.
